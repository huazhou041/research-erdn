# ERDN RNA-seq recurrence-prediction pipeline (`rnaseq_202609`)

Predicting lung-cancer recurrence from bulk RNA-seq, with a clean, self-contained,
regenerable pipeline. This repo is **code only** — all patient data, intermediate
RDS, per-patient predictions, and built reports are git-ignored and stay on the
cluster (`/gpfs/data/tsirigoslab/home/zhouh05/segal/rnaseq_202609`).

> **PHI / data governance:** `data/`, `raw_data/`, `res*/`, and all `*.rds/*.csv`
> contain patient RNA-seq + clinical metadata. They are **never** committed and must
> not be pushed to GitHub or any external host.

---

## 1. What the pipeline does

For two RNA-seq batches (`prev`, `current`) it builds model-ready matrices for a set
of patient **cohorts** × **tasks**, runs several **feature-selection × model** arms
under repeated cross-validation, aggregates AUCs, and renders interactive HTML
dashboards. It also builds an ever-smoker subset and a transfer arm using the
nature_com paper's top genes.

### Cohorts (full pipeline = 10)
`wholeset` (150), `stage1` (120 = IA1/IA2/IB), `intersection` (58 = stage-1 ∩ old
NatComm normal-tissue RNA-seq), `nonintersection` (92 = wholeset − intersection),
`novel` (74 = wholeset − full NatComm 76) — each with a `_coding` (protein-coding
only) variant. The **ever-smoker** subset uses the same cohorts minus `novel` (8).

### Tasks (recurrence label)
`recurrence = 1` iff `ProgType ∈ {1,2,3}`. `123vs0` = all; `12vs0` = ProgType {0,1,2};
`3vs0` = ProgType {0,3}. (`3vs0` is the smallest/least-powered.)

### Feature-selection arms
- `mad` — top-N by MAD, **fold-local** (ranked on training folds only; unsupervised).
- `cor` — top-N by |correlation with outcome|, **fold-local** and **supervised**.
- `mad_nosexmt` — `mad` with sex-chromosome + mitochondrial genes removed first.
- `natcommad` — **fixed external** set: the top-N nature_com MAD genes transferred to
  our data (same ranking as the dashboard Venn; no fold-local ranking, no outcome use).

### Models & AUC convention
- GLM (elastic-net, `cv.glmnet`): `--nboot 100 -k 10`.
- RF + XGB (XGB with nested inner-CV): `--nboot 50 -k 10`.
- **AUC = 100×10 (or 50×10) fold-averaged, pROC `direction="<"` (fixed, never auto).**
  Averaging per-fold AUCs with a fixed direction is unbiased for noise (~0.5); pROC's
  default `direction="auto"` would flip every sub-0.5 fold and bias AUCs upward.

## 2. Reproduce (run order)

All paths are relative to the project root on the cluster. Data must be present under
`data/` + `raw_data/` (regenerated by the build scripts from `raw_data/`).

```
# 1. Build model-ready data
Rscript codes_local/build_modeldata_*.R            # full cohorts (prev/current)
Rscript codes_local/build_modeldata_smoking_202607.R   # ever-smoker subset (inline from raw metadata)
Rscript codes_local/build_natcom_madgenes.R        # nature_com top-MAD ranking -> raw_data/natcom_mad_ranked.csv

# 2. Fit models (SLURM; idempotent, self-skip via *_group.done)
bash run_submit_20260709_glm_fsmethods.sh          # GLM mad/cor/mad_nosexmt, 10 cohorts
bash submit_rfxgb.sh                               # RF + XGB
bash submit_glm_natcommad.sh                       # GLM natcommad
bash submit_glm_smoking.sh ; bash submit_rfxgb_smoking.sh ; bash submit_glm_natcommad_smoking.sh

# 3. Aggregate per-fold AUCs
Rscript aggregate_fsmethods.R ; Rscript aggregate_rfxgb.R
Rscript aggregate_fsmethods_smoking.R ; Rscript aggregate_rfxgb_smoking.R

# 4. ROC curves (pooled) + nature_com series, then dashboards
Rscript codes_20260713/make_roc_curves_fsmethods.R ; Rscript make_roc_curves_fsmethods_smoking.R
Rscript make_roc_rfxgb_full.R ; Rscript make_roc_rfxgb_smoking.R
Rscript codes_20260713/make_dashboard_fsmethods.R          # full cohort
Rscript codes_20260713/make_dashboard_fsmethods_smoking.R  # ever-smoker
Rscript codes_20260713/make_dashboard_fsmethods_cmp.R      # full-vs-smoking toggle (MAIN report)

# 5. Deployment artifacts
Rscript extract_all_genelists.R        # per-model gene lists + coefficients/importances
Rscript foldavg_roc.R                  # vertical-averaged ROC curves (honest operating characteristic)
Rscript make_threshold_table.R         # per-config operating points + thresholds + event flags
```

Completeness targets (`*_group.done`): `res` 480, `res_rfxgb` 240, `res_smoking` 384,
`res_rfxgb_smoking` 192.

## 3. The dashboards

Main report: `htmls_20260713/auc_dashboard_20260713_fsmethods_fullVsSmoking.html`
(full ↔ ever-smoker **toggle**; all 6 models incl. **GLM+ncMAD**).

A **trimmed variant** `..._fullVsSmoking_normOnly_no3vs0.html` (built by
`make_dashboard_fsmethods_cmp_trim.R`) drops the **fpkm datatype** (keeps
normalized — marginally stronger on well-powered cohorts; the two agree only
r≈0.63 per-config) and the **3vs0** low-event task from every section.

The main report contains:
- AUC overview / heatmaps / best-model / varcut / explorer, all 100×10 fold-averaged.
- **nature_com top-MAD (GLM+ncMAD) table** after the Venn, with an own-cohort-MAD
  comparison column and CSV download.
- **Genes** download per config in the explorer (the genes each model used + weights).
- **Operating point & optimal cutoff** panel with a **Basis** toggle:
  - *Pooled* — single global probability-cutoff slider on the pooled-CV ROC (a real,
    deployable probability; unreliable / can sit below the diagonal for small-event
    configs because cross-fold probabilities aren't calibrated).
  - *Per-fold vertical-averaged* — averages each fold's ROC at fixed FPR (matches the
    headline AUC, stays above the diagonal); slider = **specificity** (no single
    cross-fold probability cutoff exists). **Youden's J** marks the optimum in both.

## 4. Final models & deploying to a new cohort

Each config's saved `.rds` under `res*/` **is** the model fit on all available data
(GLM = `cv.glmnet`; RF/XGB = `list(model, features, params)`). To score a new cohort:

1. **Choose the operating trade-off** from the *vertical-averaged* curve / table — it's
   the honest estimate of achievable sensitivity/specificity.
2. **Get a deployable probability threshold.** Start from
   `model_operating_points_202609.csv` → `pooled_youden_cutoff` for a well-powered,
   non-low-event config, then **re-derive on the final model + calibrate**.
3. **Score:** `Rscript predict_new_cohort.R <config_key> <new_expr.csv> <threshold> <out.csv>`
   — aligns the new (identically-normalized) matrix to the model's genes and outputs
   per-sample probability + class.
4. **Validate externally.** Any threshold picked on training/CV data is optimistic;
   calibrate (Platt/isotonic) and confirm on an independent cohort before real use.

**Do not deploy low-event configs** (`3vs0`, tiny cohorts) — flagged `low_event_flag`
in the operating-points table; their AUC/CI are small-sample artifacts (e.g. a narrow
CV CI there reflects resampling reproducibility, **not** true uncertainty, which is
huge with ~4 events).

### Deployment recipe (calibrated — the correct flow)
1. **Pick a well-powered, non-low-event, gene-based config** (fpkm / fpkm_clinics).
2. In the dashboard cutoff panel, set **Basis = "Calibrated CV (deployable)"** — this
   shows honest out-of-fold sensitivity/specificity on a *calibrated* probability axis.
   Read the **Youden** (or your chosen) **calibrated cutoff**.
3. **Score new patients:** `predict_new_cohort.R <config_key> <new_expr.csv> <calibrated_cutoff> <out.csv>`.
   It loads the full-data model, fits **Platt calibration (logistic regression) on the
   config's out-of-fold CV predictions** (NOT on the model's own training data), applies
   it to the new scores, and classifies at your calibrated cutoff.
4. **Validate on an independent cohort** before any real use.

Why calibrated-CV: sensitivity/specificity come from held-out CV (honest); calibration
(**Platt scaling** — a logistic fit on the OOF scores) only relabels the probability axis
so the cutoff is a meaningful, deployable number on the full model's scale. Platt is the
standard choice at these sample sizes (~60–150): it is a smooth, strictly monotone sigmoid
(preserves AUC) and, unlike isotonic, does not collapse weak-signal scores into a handful
of tied probability blocks (which produced a few-point, zig-zag ROC). The other three slider bases are diagnostic only — *pooled* (raw
CV probability, can sag below the diagonal for small-n), *vertical-averaged* (honest
trade-off but no single probability), *in-sample* (full model on its own data —
optimistic, shows the deployable scale but not real performance).

Reality check: even the best well-powered configs here reach only AUC ≈ 0.6, so any
cutoff is research-grade prioritization, not a validated clinical threshold.

Key deployment files: `model_operating_points_202609.csv` (thresholds + event flags),
`predict_new_cohort.R` (scorer), `model_gene_lists_202609.csv.gz` (every model's genes).
